# Inference Guide — Using `predict.py` on New SAR Data

This guide explains how to run oil spill detection on your own Sentinel-1 SAR
imagery and interpret the results.

---

## Prerequisites

1. Trained model weights: `best_oilspill_model.pth` (generated by
   `scripts/train.py` or download the pretrained weights)
2. Input SAR images: 2-band GeoTIFF files (VV + VH polarization)
3. Python environment set up (see `requirements.txt`)

---

## Quick Usage

### Batch Mode (Default)

By default, `predict.py` randomly selects 10 images from the test split
and generates GeoJSON reports:

```bash
python main.py predict
```

Output GeoJSON files are saved to the `reports/` directory:
```
reports/
├── oil_spill_polygons_00056.json
├── oil_spill_polygons_00178.json
└── ...
```

---

## Understanding the Output

Each GeoJSON file is a standard **FeatureCollection** containing one or more
oil spill polygons:

```json
{
    "type": "FeatureCollection",
    "crs": {
        "type": "name",
        "properties": {
            "name": "EPSG:4326"
        }
    },
    "features": [
        {
            "type": "Feature",
            "properties": {
                "class": "oil_spill"
            },
            "geometry": {
                "type": "Polygon",
                "coordinates": [[[lon1, lat1], [lon2, lat2], ...]]
            }
        }
    ]
}
```

### Key Fields

| Field | Description |
|---|---|
| `crs` | Coordinate Reference System (from the input GeoTIFF) |
| `features[].geometry` | Polygon boundary of detected oil spill |
| `features[].properties.class` | Always `"oil_spill"` |

### When No Output is Generated

If the model detects no oil in an image (or all detections are below the noise
threshold), **no JSON file is created** for that image. A console message will
indicate this:

```
[*] No oil spills detected in this image. No JSON generated.
```

## Configurable Parameters

These are defined as constants at the top of `predict.py`:

| Parameter | Default | Description |
|---|---|---|
| `MODEL_PATH` | `"best_oilspill_model.pth"` | Path to trained model weights |
| `ENCODER` | `"resnet34"` | Must match the encoder used during training |
| `NUM_CLASSES` | `5` | Number of segmentation classes |
| `OIL_CLASS` | `1` | Class index for oil spill |
| `NOISE_THRESHOLD` | `50` | Minimum pixel cluster size to retain (smaller = more sensitive, more noise) |
| `OUTPUT_DIR` | `"./reports"` | Where GeoJSON outputs are saved |

---

## Noise Threshold Tuning

The `NOISE_THRESHOLD` parameter controls the minimum connected-component size
(in pixels) that is considered a valid oil spill detection:

- **Lower values (e.g., 10)**: More sensitive, catches smaller spills, but also
  retains more speckle noise false positives
- **Higher values (e.g., 100)**: More conservative, only reports larger spill
  regions, may miss small or narrow spills
- **Default (50)**: Balanced for the Krestenitis dataset characteristics

## Visualizing Results in QGIS

1. Open QGIS and load a basemap (e.g., OpenStreetMap)
2. Drag the output `.json` file into QGIS — it will be recognized as a GeoJSON
   vector layer
3. Style the polygons (e.g., red fill with 50% opacity) to visualize spill
   boundaries on the map
4. Compare against the original SAR raster (load the `.tif` file as a raster
   layer) to verify alignment

---

## Input Format Requirements

The model expects:
- **Format**: GeoTIFF (`.tif`)
- **Bands**: Exactly 2 (Band 1 = VV, Band 2 = VH)
- **Pixel type**: Float32 (raw radar backscatter values)
- **CRS**: Any valid CRS (preserved in output); EPSG:4326 recommended
- **Size**: Any resolution (will be resized to 256×256 internally)

If your SAR data has more than 2 bands, you'll need to extract VV and VH before
running inference.

---

## Downstream Integration

The GeoJSON output is designed as the first step in the PS #26143 pipeline:

```
SAR GeoTIFF → [predict.py] → GeoJSON polygons
    → Centroid extraction
    → OpenDrift backward drift simulation
    → AIS vessel track matching
    → Investigation dashboard
```

The polygon centroids and timestamps can be fed directly into OpenDrift to
simulate where the spilled oil originated, enabling cross-reference with
vessel positions from AIS data.
